# EcoTrack

EcoTrack is a full-stack utility-tracking platform for households: upload or manually enter
electricity/water bills, track appliance costs, set budgets, get bill predictions and anomaly
alerts, manage notifications, and export personal or admin reports. It has separate customer and
admin workflows, backed by MongoDB and a simple session-token auth scheme (no JWT, no 2FA — see
Authentication below, this is an intentional final design decision, not a gap).

## Tech stack

- **Frontend**: React 19 + Vite, `react-router-dom`, Recharts for charts.
- **Backend**: Java 17, Spring Boot 3.2.5, Spring Data MongoDB, Spring Mail.
- **Database**: MongoDB (local or Atlas).
- **File handling**: Apache POI (Excel import/export), Apache PDFBox (PDF text extraction and
  PDF report generation), tess4j/Tesseract (optional OCR for scanned bill images).
- **Build tools**: Maven (`mvnw`/`mvnw.cmd`) for the backend, npm/Vite for the frontend.

## Features

- Signup/login with OTP email verification, forgot/reset password, admin login.
- Per-user bill management: manual entry, OCR-assisted upload (PDF/JPG/PNG — including scanned,
  image-only PDFs, which are rendered and OCR'd), document storage and download, payment status
  tracking (with a scheduled job that flips overdue bills).
- Meter-photo reader: snap the meter, OCR suggests a reading (digits only) that you confirm or
  correct before saving — a number is never invented.
- Appliance tracker with cost breakdown (daily/monthly/annual) and rule-based savings tips.
- Tariff catalog (admin-managed) used for billing estimates.
- Bill amount predictions and unusual-consumption (anomaly) detection.
- Budget management with threshold alerts.
- Notifications (payment reminders, overdue alerts, budget/anomaly alerts, monthly summaries)
  with per-category email preferences, generated by a scheduled job.
- Personal reports/exports (Excel and PDF): monthly electricity/water reports, combined expense
  report, appliance expense report, payment history, and annual report.
- Admin panel: user list + per-user activity history, Excel export of all users, and a system
  analytics panel (user/bill/appliance counts, verified vs. unverified, roles, recent signups).

## Authentication

Sessions use a simple opaque `X-Session-Token` header issued on login and checked server-side
(`AuthService.requireUser`/`requireAdmin`) — there is deliberately no JWT, no refresh-token
flow, no 2FA, and no multi-device session management. This is the final, intended design for
this project, not a placeholder.

## Getting started

### Prerequisites

- Java 17 (JDK)
- Node.js 18+ and npm
- A MongoDB instance — either local (`mongodb://localhost:27017`) or a MongoDB Atlas cluster
- (Optional) Tesseract OCR installed natively, needed for text extraction from **image** bill
  uploads, scanned (image-only) PDFs, and the meter-photo reader. Digital PDFs use PDFBox and
  always work without it. If Tesseract isn't installed, OCR silently degrades
  (`ocrAvailable: false` plus a `reason` in the response) instead of failing the upload — the
  upload page keeps working exactly as before, with manual entry as the fallback.
  - Windows: install from https://github.com/UB-Mannheim/tesseract/wiki (the default
    `C:\Program Files\Tesseract-OCR` location is fine).
  - macOS: `brew install tesseract`
  - Linux (Debian/Ubuntu): `sudo apt-get install tesseract-ocr`

  Tesseract does **not** need to be on your `PATH` — the backend only needs the **tessdata**
  folder (the one containing `eng.traineddata`). It is resolved in this order:
  1. the `app.ocr.tessdata-path` property in `application.properties`,
  2. the `TESSDATA_PREFIX` environment variable,
  3. the common install locations (`C:\Program Files\Tesseract-OCR\tessdata`,
     `C:\Program Files (x86)\Tesseract-OCR\tessdata` on Windows; the usual
     `/usr/share/tesseract-ocr/...` paths on Linux; Homebrew paths on macOS).

  On startup the backend logs a self-check line, e.g.
  `OCR self-check: available. tessdataPath=C:\Program Files\Tesseract-OCR\tessdata, languages=[eng, osd], psm=6, maxPdfPages=10.`
  See **Windows OCR setup** and **OCR troubleshooting** below.

### 1) Backend configuration

Copy the example config and fill in your own values:

```bash
cd backend/src/main/resources
cp application.properties.example application.properties
```

Edit `application.properties`:

- `spring.data.mongodb.uri` — your MongoDB connection string (local or Atlas).
- `spring.mail.username` / `spring.mail.password` — a Gmail address + App Password for sending
  OTP emails. If you leave `otp.demo-fallback-enabled=true` (the default in the example), the
  app still works without real email configured: OTPs are also returned in the API response for
  local testing.
- `app.uploads.dir` — local disk folder where uploaded bill documents are stored (created
  automatically on startup if missing).
- `database.reset-on-startup` — keep `false` unless you want every start to wipe users/history.

### 2) Run the backend

```bash
cd backend
./mvnw spring-boot:run
```

On Windows PowerShell:

```powershell
cd backend
.\mvnw.cmd spring-boot:run
```

The backend listens on `http://localhost:8080` by default. Set `BACKEND_PORT` in the
project-root `.env` to use a different port. A default admin account is bootstrapped on first
run: `admin@ecotrack.com` / `Admin@123`.

### 3) Run the frontend

```bash
cd frontend
npm install
npm run dev
```

The frontend runs on `http://localhost:5173` by default; set `FRONTEND_PORT` in the
project-root `.env` to change it. Set both `BACKEND_PORT` and `VITE_BACKEND_PORT` to the same
value when changing the backend port. `VITE_API_BASE` can still override the full frontend API
URL.

### Running tests / checks

```bash
# Backend
cd backend
./mvnw.cmd test        # or ./mvnw test on macOS/Linux

# Frontend
cd frontend
npm run build
npm run lint
```

See `TEST_RESULTS.md` for the latest verification pass.

## Windows OCR setup

Tesseract just needs to be installed; the backend finds it automatically. To use a custom install,
point `app.ocr.tessdata-path` at the folder that contains `eng.traineddata` (use forward slashes):

```properties
# backend/src/main/resources/application.properties
app.ocr.tessdata-path=C:/Program Files/Tesseract-OCR/tessdata
app.ocr.language=eng
app.ocr.psm=6
app.ocr.max-pdf-pages=10
```

Confirm the install and that the language file is present:

```powershell
& "C:\Program Files\Tesseract-OCR\tesseract.exe" --version
Get-ChildItem "C:\Program Files\Tesseract-OCR\tessdata\eng.traineddata"
```

Then verify from a running backend (no login required):

```powershell
curl http://localhost:8080/api/ocr/status
# {"available":true,"tessdataPath":"C:\\Program Files\\Tesseract-OCR\\tessdata","languages":["eng","osd"],"reason":null}
```

If `eng.traineddata` is genuinely missing, download it from the `tessdata_fast` or `tessdata`
repository (https://github.com/tesseract-ocr/tessdata_fast) and place it directly inside the
`tessdata` folder shown by `GET /api/ocr/status` (or by the startup self-check log).

## OCR troubleshooting

`GET /api/ocr/status` (and the `reason` field on upload/meter responses) tells you exactly what
went wrong. The main cases:

| `reason` (abridged) | Meaning | Fix |
| --- | --- | --- |
| `Tesseract tessdata for 'eng.traineddata' was not found. Looked in: ...` | No usable tessdata folder was found. The reason lists every path that was checked. | Install Tesseract, or set `app.ocr.tessdata-path` to the folder containing `eng.traineddata`. |
| `OCR self-check failed (<exception>): <message>` | The tessdata folder was found but probing it threw. The real exception class and message are included. | Read the logged exception; usually a permissions issue on the tessdata folder. |
| `The OCR engine failed (<exception>): <message>` | Tesseract's native library failed during recognition (e.g. a missing DLL or a corrupt traineddata file). | Re-install Tesseract; make sure `tesseract.exe` and its DLLs are intact. |
| `No readable text was found in the image.` | OCR ran but found nothing — a blank or very blurry photo. | Retake the photo with more light and less blur. |
| `The file could not be decoded as an image. Try a JPG or PNG.` | The upload wasn't a readable JPG/PNG (corrupt or wrong extension). | Upload a clean JPG/PNG (max 10 MB). |
| `This PDF has no text layer, so it needs OCR to be readable.` | A scanned PDF, and OCR is unavailable. | Install/enable Tesseract, or enter the bill manually. |
| `No text could be extracted from the PDF — it may be blank or corrupt.` | PDFBox found nothing and either OCR wasn't needed or also found nothing. | Check the PDF opens elsewhere; otherwise enter the bill manually. |
| `No digits were found in the photo...` / `The photo was read but no meter digits were recognised` | Meter OCR ran but couldn't isolate a reading. | Type the reading in manually — the UI never invents a number. |
| `Extraction failed (<exception>). You can still enter the bill manually.` | An unexpected error during extraction. | The upload page still works; enter the bill manually. |

OCR never breaks a request: every failure comes back as HTTP 200 with `ocrAvailable: false` and a
`reason`, and the upload page falls back to manual entry.

## Notes

- OTP verification falls back to a demo mode (OTP returned in the API response) when live email
  delivery isn't configured — controlled by `otp.demo-fallback-enabled`.
- Uploaded bill documents are stored on local disk under `app.uploads.dir`; file access is
  guarded against path traversal and scoped to the owning user (or an admin).
- All personal data (bills, appliances, budgets, notifications, recommendations, reports) is
  scoped per-user; cross-user access is rejected with 403/404 responses.
